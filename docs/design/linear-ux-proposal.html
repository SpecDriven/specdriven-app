UI / UX proposal · SpecDriven desktop

SpecDriven, Linear-grade

Nine changes that turn the current web-page feel into a dense, keyboard-first desktop tool, modeled on Linear. This page is set in the proposed token system, so what you're reading is the sample.

Direction · shift toward Linear's look Scope · proposal only, no code Focus · palette, header, status, feedback

Where it stands

The frontend is React 19 with hand-written CSS, no component library, no router, no icon set. One App() component holds every view, dialog and fetch. It works, and it reads as a web page rather than a desktop tool:

  • Actions are text links. "Edit · Copy link · Edit description · Publish" strung across the feature header; four links per scenario card.
  • Icons are unicode. ✎ ✕ ▸ ▾ ⋯ ⚙ ✓ 🔗 🖼 ▶ plus four hand-drawn SVG files.
  • Status is a word badge on cards only. The sidebar tree shows nothing about a feature's state.
  • Search swaps out the tree. No command menu, no action search.
  • Feedback is one status line. Fifty setStatus() call sites land in the same <p>, styled the same for "Moved" and "Publish failed", never auto-dismissed.
  • Hover-only row menus. The tree's ⋯ and folder delete use visibility: hidden until hover, so keyboard users can't reach them.
  • Ten separate keydown listeners share one hand-maintained "Escape owned elsewhere" flag.

What "Linear-like" means here

Keyboard first

Every action reachable via ⌘K; single keys for the top ten; every tooltip and menu item shows its key.

Quiet chrome, dense content

13px UI text, 1px low-contrast borders, 6px radii. No shadows on panes; shadows only on popovers and dialogs.

Status is a glyph

One icon vocabulary for draft, proposed, published, used identically in tree, cards, editor, palette, filters.

Properties are chips

Assignee, ticket, status are pill buttons opening a searchable popover. Never a native select, never a text link.

Feedback is reversible

Toasts with Undo. Autosave shows a quiet "Saved" indicator in the header, not a banner.

One implementation per pattern

One Menu, one Popover, one Tooltip, one Toast, one shortcut dispatcher, one Icon component.

The whole picture

1Command palette

Actions available by name: New feature, New folder, New scenario, Publish, Publish all, Propose, New version, Copy link, Rename, Move to folder…, Delete, Sync now, Start code-gen session, Toggle sidebar, Theme: light / dark / system, Settings, Change data repo, Open README, Open roadmap page…

The sidebar search field stays and opens the palette prefilled, as Linear's sidebar search does. Fixes the half-built combobox at App.tsx:3460 with role="combobox", aria-expanded, aria-controls, aria-activedescendant.

4Property chips with popover menus

Status, Assignee, Ticket and version become 24px chips under the header. Clicking one opens a popover anchored below: a searchable list with ↑↓ ⏎ Esc, a checkmark on the current value, and an optional key hint per row. Assignee rows show a 16px avatar built from the same initials logic as the user corner.

One Menu component backs the chip popovers, the tree ⋯ menu, the recent-repos menu, the user menu, and right-click menus. It owns outside-click, Escape, typeahead, Home/End, menu roles, and focus return.

Replaces the Assigned <select> (App.tsx:4030-4047) and the three per-menu effects (933-998). ExternalLinkField.tsx moves inside the Ticket popover; externallinks.ts is unchanged.

6Sidebar: collapse, hierarchy, filters, keyboard tree

  • Collapse on [ or the header icon. Collapsed keeps a 44px rail with logo, ⌘K and a hover-to-peek flyout. Persisted next to sd-sidebar-width.
  • Sections in Linear order: workspace switcher (repo name + recents), primary nav (Home, Roadmap, My specs = features assigned to me), then the Features tree. Section headers 11px uppercase, collapsible.
  • Filter row above the tree adds chips for status and assignee. Non-matching tree rows dim; non-matching cards hide. There is no filtering today.
  • Tree semantics: role="tree" / treeitem / aria-level / aria-expanded; ↑↓ move, ←→ collapse and expand, ⏎ opens, ⋯ menu on ⇧F10. Row actions become visible on :focus-within, not just hover.
  • Drag and drop keeps working, with a 2px insertion line and an accent-soft drop highlight on folders.

7Feedback, loading, accessibility

  • Toast system. Bottom-left stack. Success auto-dismisses after 3.5s; errors stay until dismissed; optional Undo with a 5s window. Success uses aria-live="polite", errors role="alert". Undo wires to delete draft, delete folder, move feature, unassign. The server already has the inverse operations.
  • Saved indicator. README, roadmap and description autosave stop toasting; the header shows Saving… / Saved · 2s ago / Unsaved.
  • Skeletons for the feature page (header + three card outlines), palette results, roadmap page, with aria-busy on the pane.
  • Error boundary around the main pane with a "Reload view" button.
  • Dialogs all get role="dialog" and aria-modal="true"; the code-gen session error dialog gets the focus trap and Escape like the others.
Replaces .saved-banner (App.tsx:3337), fifty setStatus() sites, the lone "Loading…" (3284), and the untrapped alert dialog (5003).

8Roadmap polish

  • Rename and delete from the same ⋯ menu. Server: add DELETE /api/roadmap/:file; removeRoadmapDoc already exists in the Automerge store.
  • Nested pages grouped by folder with indentation. listRoadmap already returns the path; the sidebar prints only the name today.
  • Same breadcrumb header and Saved indicator as feature pages.

9Icons and tooltips

Vendor Lucide as inline SVG components, bundled with the app like the fonts so the desktop build stays offline. Every unicode glyph and the four hand-drawn icon files go. A Tooltip component with a 350ms delay, 12px text and a <kbd> suffix wires to every icon button via aria-describedby.

Spec change to apply

The spec repo is never edited from a session, so this is the replacement text for the Design system section of specs/ui/ui.feature.md, for you to paste in:

Quiet, dense, keyboard-first, Linear-like. All colors flow through CSS tokens in src/frontend/index.css; components never hardcode a color. Surfaces: white canvas, faint-grey sidebar (light); near-black equivalents (dark). Accent: indigo, used for primary buttons, focus rings, and the active row. Status has its own three colors (draft grey, proposed amber, published green) shown as glyphs, never as text badges. Type: Inter for all UI text at 13px; JetBrains Mono for code and file names; fonts ship with the app. Borders are 1px low-contrast; radii 4–8px; shadows only on popovers and dialogs. Focus is always visible. Every action is available from the ⌘K command menu, and every menu item and tooltip shows its shortcut.

While there: the "Draft checkbox" rule in the same file (lines 112–119) still reads as current, but the editor uses Propose / Publish buttons and a status badge. Mark it superseded.
