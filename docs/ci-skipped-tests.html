Why some tests are skipped on CI

SpecDriven · test suite audit · generated 2026-11-07 · verified against main

The short version. CI runs bun test on a single ubuntu-latest runner (.github/workflows/test.yml). Nothing is skipped because “it’s CI” — there is no process.env.CI gate anywhere in the suite. Instead, individual tests use Bun’s test.skipIf(…) keyed on capability: is a given binary installed, is the process root, and which OS is this. On the GitHub runner three of those conditions are what they are — Linux, non-root, no PowerShell in the main run — so a handful of tests skip by design.

Separately, CI adds coverage the local default doesn’t: it sets SPECDRIVEN_ALL_ENGINES=1, fanning the git push/pull tests across all three engines (cli/gh/js). And the Electron desktop crash test (test:desktop) is not wired into any workflow at all — it only runs locally.

How CI is wired

.github/workflows/test.yml — three jobs, all runs-on: ubuntu-latest, Bun 1.3.14, no OS matrix:

  • test — bun test with SPECDRIVEN_ALL_ENGINES: "1". No name filter, no path filter; the test scope comes entirely from bunfig.toml.
  • typecheck — bun run typecheck (tsc --noEmit -p .).
  • audit — bun audit with two advisories intentionally ignored (reasons documented inline in the workflow).

bunfig.toml pins [test] root = "tests", so only the app’s own tests under tests/ are collected — *.test.ts files the desktop crash test leaves behind under dist/ (from auto-installed plugins) are excluded. The release workflows (release.yml, release-windows.yml) only build; they do not run bun test.

The five reasons in detail

1PowerShell installer tests — moved to their own workflow

Every test in tests/installPs1.test.ts is gated on PowerShell being named via an env var:

const PWSH = process.env.SPECDRIVEN_TEST_PWSH;   // installPs1.test.ts:35
test.skipIf(!PWSH)("the latest release is downloaded, verified and unpacked ...", ...)

The main suite (test.yml) never sets SPECDRIVEN_TEST_PWSH, so all 20 skip. A dedicated workflow, .github/workflows/install-ps1.yml, sets it and runs just that file — but only when the installer, its test, or its helpers change (a paths: filter):

run: SPECDRIVEN_TEST_PWSH="$(command -v pwsh)" bun test tests/installPs1.test.ts

Stated reason (installPs1.test.ts:8-14, install-ps1.yml:3-7): the script runs under PowerShell 7 and spins one up on every run — too slow to pay on every pull request, so these are opt-in.

2Plugin file-watch test — skipped because CI is Linux

test.skipIf(process.platform === "linux")(
  "the app watches a plugin under development and rebuilds it as it is edited",
  ...)                                            // pluginSources.test.ts:200

CI runs on ubuntu-latest, so this one always skips there. The test writes a plugin file, then polls for the rebuilt route to answer within a deadline. That watch→rebuild race is timing-sensitive on Linux, where Bun’s recursive fs.watch walks the directory tree differently than the macOS FSEvents path. The non-watch build/rebuild behaviour is still covered by the preceding, un-skipped test in the same file, so coverage of the loader itself isn’t lost — only the live-edit watcher path goes unverified on CI.

3Worker-isolation tests — need root + setpriv

const isolated = workerIsolation();             // gatewayWorkers.test.ts:126
test.skipIf(!isolated)("each worker runs as its own uid, owning its folder alone", ...)
export function workerIsolation(env = process.env): boolean {   // src/gateway/workers.ts:100
  if (env.SPECDRIVEN_WORKER_ISOLATION === "off") return false;
  return process.getuid?.() === 0 && Bun.which("setpriv") !== null;
}

It returns true only when the process is root and setpriv is installed. GitHub’s default ubuntu-latest runner is non-root, so this skips. It would run in the hosted image or a root CI container.

Stated reason (gatewayWorkers.test.ts:124-125): “Separate uids need root and setpriv … elsewhere these tests have nothing to check.”

4Optional-binary installer tests — skip when the tool is missing

tests/install.test.ts looks up tools with findTool(name), which returns null if the binary isn’t in a fixed set of directories, and skips the test that exercises it:

test.skipIf(!wget)("wget does the job when there is no curl", ...)       // :601
test.skipIf(!bsdtar)("bsdtar unpacks the zip when unzip is missing", ...) // :617
test.skipIf(!PYTHON)("a yes at the terminal installs Bun, ...", ...)      // :711, :730, :743

These are environment-dependent rather than always-off. On ubuntu runners python3 is normally present (so those run); wget/bsdtar may be absent and skip. They cover alternative downloader / unzip / interactive paths.

5Context: the git-engine matrix is the opposite of a skip

Don’t confuse this one for a skip. Locally the push/pull tests run on a single engine (cli). CI sets SPECDRIVEN_ALL_ENGINES=1, so tests/helpers/engines.ts fans them across cli, gh and js. CI runs more here, not less — each engine costs a full fixture plus a real commit/push, which is too slow to triple locally.

Also worth knowing. There is no test:ci script and no .only anywhere — CI just calls bun test and injects the engine flag via workflow env. The desktop/Electron crash test (package.json → "test:desktop": "bun scripts/crash-test-desktop.ts") is not run by any workflow, so it’s effectively a local-only gate before releases.

Running the skipped tests locally

  • PowerShell installer tests: SPECDRIVEN_TEST_PWSH="$(command -v pwsh)" bun test tests/installPs1.test.ts (needs PowerShell 7; the python-terminal case also needs python3).
  • Plugin watch test: run on macOS (or any non-Linux host) — bun test tests/pluginSources.test.ts.
  • Worker isolation: run as root on a box with setpriv installed, and don’t set SPECDRIVEN_WORKER_ISOLATION=off.
  • wget / bsdtar paths: install those binaries so findTool can locate them.
  • Desktop crash test: bun run test:desktop (local only; see project limits on how many on-screen launches per verification).
